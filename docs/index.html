Latchkey

Firmware for ESP32 boards that pairs, manages and hardens a TTLock Bluetooth LE smart lock with no cloud and no phone, behind an owner-only web UI.

Early development: the protocol core, the USB serial console and claiming the board work today; pairing from the board, the web UI on the board, HTTPS, TOTP login, button confirmation, hardening and key backup are being built. See the source and status on GitHub.

Flashing erases the board

The factory image rewrites the flash from address 0: bootloader, partition table and every setting stored on the board, including the owner claim, the Wi-Fi settings, the audit log and the keys of any lock paired with it. Whatever was on the board before is gone, whether or not you also choose to erase it in the installer.

If this board manages a lock, that lock can no longer be managed from it. A lock whose reset button is still enabled can be returned to factory state with that button and paired again; after hardening has disabled the button, only an encrypted key backup restored on a board gets the lock back.

1. Pick the board

Board

An M5 ATOM is a classic ESP32, but its button is on GPIO39: the classic image reads GPIO0, so the ATOM needs a build with LATCHKEY_BUTTON_GPIO=39. See the hardware notes.

2. Install

No release has been published on this site yet. Build and flash from source as the README explains.

Connect the board over USB, then install version . This needs Chrome or Edge on a desktop computer: the installer talks to the board through Web Serial.

This browser cannot open serial ports. Use Chrome or Edge on a desktop computer, or flash with esptool. The installer only works on an HTTPS page.

Files for this board: (flash at 0x0), (update over the air), SHA256SUMS, release notes.

Prefer the command line? Download the factory image and SHA256SUMS, check one against the other (shasum -a 256 instead of sha256sum on macOS), then write the image at 0x0 with esptool 5 (--chip esp32s3 for the S3 image):

sha256sum --check --ignore-missing SHA256SUMS
esptool --chip esp32 --port <port> write-flash 0x0 latchkey-<version>-esp32-factory.bin

3. Claim it over USB

A fresh board has no owner. Claiming happens only over the USB serial console, which counts as physical presence: send system.setup with tools/latchkey_cli.py from a checkout of the repository. The Wi-Fi settings need a static IPv4 address; the owner password is 12 to 128 bytes.

git clone https://github.com/giovannirco/latchkey.git
cd latchkey
uv run -q --no-project --python 3.14 --with pyserial==3.5 \
  python -I tools/latchkey_cli.py --port <port> system.info
uv run -q --no-project --python 3.14 --with pyserial==3.5 \
  python -I tools/latchkey_cli.py --port <port> system.setup - < setup.json

setup.json, which keeps the passwords out of your shell history:

{
  "wifi": {
    "ssid": "your-network",
    "password": "your-wifi-password",
    "ip": "192.0.2.50",
    "gateway": "192.0.2.1",
    "netmask": "255.255.255.0",
    "dns": "192.0.2.1"
  },
  "password": "a long owner password"
}

The reply carries an otpauth:// URI, once: add it to an authenticator app for the TOTP codes of the web login, then delete setup.json. The port is /dev/cu.usbserial-* or /dev/cu.usbmodem* on macOS, /dev/ttyUSB* or /dev/ttyACM* on Linux and COM* on Windows.

Not supported

  • ESP8266 boards: they have no Bluetooth radio, and TTLock locks only talk Bluetooth LE.
  • Other ESP32 chips (C3, C6, H2 and so on): there is no build for them yet.

Latchkey is free software under the GPL-3.0-or-later. The TTLock protocol work builds on kind3r/ttlock-sdk-js and roquerodrigo/ttlock-ble. The installer is ESP Web Tools 10.4.0 (Apache-2.0), loaded from unpkg with every module pinned by its SHA-384 hash. Security model.
